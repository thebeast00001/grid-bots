# Lists and Trackers Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Grid keeps your lists, so bots don't just answer in prose. Groceries, packing and to-dos are checklists, habits are trackers with streaks, and expenses add up. Bots create and change them from plain words. They show as live cards in chat and in a Lists tab where you tick, add, reorder, rename, share as text and delete.

**Architecture:**
- **Storage:** three tables. `lists` (kind: checklist | habits | expenses), `list_items`, and `habit_checkins` (one row per habit per day).
- **Logic:** a repo builds the `ListView` the UI and the tools share: counts, streaks and totals, computed in the user's time zone. Every change publishes a `lists` event, so cards, the Lists tab and other tabs refresh.
- **Bots:** five tools (`create_list`, `find_lists`, `read_list`, `change_list`, `log_expense`); there is no tool to delete a list.
- **Chat:** a tool result carrying a list id renders a card that shows the list now, not as it was.

**Tech Stack:** as before. Reordering uses Motion's `Reorder` with a drag handle (mouse and touch); dates use luxon.

**Spec:** `docs/superpowers/specs/2026-11-19-next-50-features-design.md` → feature 5.

## What you see

- "Make me a packing list for Goa: sunscreen, swimsuit, charger." The bot answers with a checklist card. Tick items right there.
- "Add milk and eggs to groceries" (to any bot): the same card everywhere ticks forward live.
- "Track my habits: run, read 20 pages" makes a habits card with today's boxes.
  - "I went for a run" checks today in.
  - Each habit shows its last 7 days and its streak.
- "I spent 250 on lunch" logs it to Expenses (made the first time), with this month's total.
- A **Lists** tab (rail on desktop, header on phone) shows every list with its progress. Opening one gives:
  - add with Enter;
  - tick, and done items fold away under "Done (3)";
  - drag the handle to reorder;
  - tap a name to rename it;
  - Share (copies the list as text, or opens the phone's share sheet);
  - Delete, with a confirmation;
  - for habits, a 7-day grid you can tap; for expenses, newest first, with totals.

## Global Constraints

- **Kinds:** `checklist` (groceries, packing, to-dos), `habits`, `expenses`.
- **Ownership:** lists belong to the user. Any bot can find, read and change any list. A list remembers the bot that made it (`bot_id`, set to null when that bot is deleted, so the list stays).
- **Limits:** list name 1–80 characters; item text 1–200; 300 items per list; 200 lists; 50 items per tool call; amounts 0 to 1,000,000,000.
- **Order:**
  - Checklist and habit items keep a `position`; new ones go last.
  - Checklists show open items in order, then done items (most recently done first).
  - Expenses show by `spent_on` (newest first), then newest added.
- **Habits:** check-ins are days (`YYYY-MM-DD`) in the user's zone. A streak counts consecutive checked days ending today, or ending yesterday if today isn't checked yet. The view carries the last 7 days.
- **Expenses:** amounts are stored in hundredths (integer). Currency is an optional ISO 4217 code on the list (never guessed). The view carries `total` and `month` (this calendar month, user's zone). Display uses `Intl.NumberFormat` with the currency if set, otherwise a plain 2-decimal number.
- **Share text:**
  - Checklist: name line, then `☐ item` for open and `☑ item` for done.
  - Habits: `Run — 5-day streak`.
  - Expenses: `Lunch — 250.00 (19 Nov)` per item, then `Total: 1,240.00`.
- **Events:** `{ type: "lists" }` on every change (create, rename, delete, items, check-ins, reorder).
- **Bots can't delete lists** (a web page can't talk one into it). They can add, tick, untick, edit and remove items. Users delete lists in the Lists tab, after a confirmation.
- **Tool outputs are small:** `{ ok, list: { id, name, kind, open, done, total? } }`, plus ids of added items. `read_list` returns items as `{ id, text, done, amount?, spentOn?, streak?, today? }`.

## Review Focus

1. **Two tabs ticking the same item** → both settle on the server's state (events refresh both). (Task 4 e2e: a card and the list page update together.)
2. **A habit checked at 11:50 pm, then midnight passes** → yesterday stays checked, the streak holds until the end of today. (Task 1 tests with a fixed clock and zone.)
3. **Expenses across a month boundary and in another zone** → `month` counts the user's calendar month. (Task 1 tests.)
4. **A bot deleted while its lists exist** → lists stay, with no maker. (Task 1 test.)
5. **301st item, 201st list, 51 items in one call** → refused with a plain reason. (Tasks 1 and 3 tests.)

### Task 1: Storage and views

**Files:** `lib/db/schema.ts` + migration `0006_lists.sql` (drizzle-kit), `lib/lists/repo.ts` (+test), `lib/lists/format.ts` (+test: amounts, share text), `lib/events.ts`, `lib/client-types.ts`, `app/api/test/reset/route.ts`

**Interfaces (produced):**
- `ListView = { id; name; kind; botId: string | null; currency: string | null; createdAt; updatedAt; items: ItemView[]; open; done; total?; month?; days?: string[] }`
- `ItemView = { id; text; done; doneAt; position; amount: number | null; spentOn: string | null; checkins?: string[]; streak?: number }`
  - `amount` is in hundredths.
  - For habits: `checkins` holds the checked days among the last 7 (`days`).
- `createList({ name, kind, botId?, currency?, items? })`
- `listLists()` → `ListView[]` without items, but with counts (newest change first)
- `getList(id)`
- `renameList(id, name)`
- `deleteList(id)`
- `addItems(listId, items: { text; amount?; spentOn? }[])`
- `updateItem(listId, itemId, { text?; done?; amount?; spentOn? })`
- `removeItems(listId, ids)`
- `reorder(listId, ids)`
- `checkIn(listId, itemId, day, on: boolean)`

All take an optional `now` and zone where it matters. Errors are `HttpStatus` with plain messages.
